# 모델 배분 원칙 (민지희 대표 요청, 2026-11-19)

토큰은 아끼되 결과물이 알맞게 나오도록, 일의 성격에 맞는 모델에 맡긴다.
메인 세션은 판단·확정·사용자와의 대화만 맡고, 손이 많이 가는 일은 Agent 도구의 `model` 로 넘긴다.

| 일 | 맡길 곳 | 이유 |
|---|---|---|
| 방향 결정, 구성안, 팩트체크 최종 판단, 사용자 피드백 해석 | 메인 세션 | 맥락과 판단이 필요함 |
| 원고 초안 쓰기, 원고 다듬기·분량 조절, 말투 맞추기 | `model: sonnet` | 글 품질은 필요하지만 판단은 메인이 이미 내림 |
| 웹 검색 결과 요약, 기사·페이지 읽기, 녹취 정리, 글자 수 세기, 한글 파일 렌더링 확인 | `model: haiku` (또는 web-fetch 에이전트) | 기계적이고 반복적인 일 |

규칙
- 넘길 때는 파일 경로, 지켜야 할 사실 목록, 형식 규칙, 목표 분량을 브리프에 분명히 적는다. 새 사실을 지어내지 말라고 명시한다
- 결과는 메인이 짧게 확인(diff·글자 수)한 뒤 커밋·전달한다. 같은 일을 메인이 다시 하지 않는다
- 사실 확인은 원고에 실제로 들어가는 문장에만 한다
- 사용자에게 보내는 답은 짧게: 결론 → 바뀐 것 → 확인할 것
- 한 번에 끝낼 수 있는 작은 일(파일 한 줄 수정, 렌더링 한 번)은 넘기지 말고 메인이 바로 한다
